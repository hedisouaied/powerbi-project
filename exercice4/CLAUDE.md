# CLAUDE.md — exercice4 (Mission Control web app)

This is the exercice3 Power BI dashboard rebuilt as a web app:
- `backend/`: Laravel 13 + MySQL 8, run in **WSL Ubuntu**;
- `frontend/`: React + TypeScript + Vite, run with **Windows Node 22**.

The design and numbers must stay **identical to the Power BI dashboard**. The user asked for "same what I see in Power BI".

## Rules

**Same dashboard as Power BI.**
- `frontend/src/mc/` is exercice3's visual code (engine, modules, `visual.less`), adapted by `tools/webify.js`.
- Visual or calculation changes should normally be made in exercice3 too.
- Only web concerns differ:
  - API sync (`Store.sync`, `Store.revert`);
  - the signed-in user and sign-out (`App.user`, `App.onLogout`);
  - browser download (`App.exporter`);
  - wording (no Power BI mentions).

**Same tables and relationships as exercice3.**
- `backend/config/mission_control.php` is generated by `node tools/gen-schema.js` from `exercice3/tools/schema.txt`, its `build-pbip.ps1` relationship list and the CSVs. Don't hand-edit it.
- Inactive role-playing date links to `dim_date` are indexed, not enforced, because 5 rows fall outside the calendar, including the planted O00008. All other relationships are real foreign keys.

**Reference values must match Power BI.**
- Net revenue 61,746,871.96; gross revenue 73,550,210.26; open incidents 120; open alerts 210.
- Check with `php artisan mc:import --check`.
- `/api/feeds` must equal `exercice3/tools/csv-feeds.js` for all 31 tables.

**Secrets.**
- `backend/.env` holds the MySQL password (user `mission_control`) and `APP_KEY`. Never print it or commit it.
- MySQL `root` has no password from WSL user `hedi`. Use it only for admin tasks: creating databases, granting rights, cleanup.
- API keys stay fake placeholders. The user declined real keys.

**Run the tests against test data.**
- Backend tests use the `mission_control_test` database (`phpunit.xml`).
- `tools/e2e.js` deletes the task it creates.
- After manual checks, remove test rows: `Web task %` tasks, and `activity_log` rows whose id starts with `WEB`.

**Do the work; don't hand the user homework.** Don't take their screen; use headless Chrome. See the user's memory notes.

## French (the app is entirely in French)

The user asked for French everywhere: interface, API messages and the data.

**Data:**
- The CSVs stay English (source). `mc:import` translates every text column with `backend/database/data/translations_fr.json` and writes French to MySQL.
- `translations_fr.json` has one shared `values` dictionary, `patterns` for numbered texts, and `keep` for untranslated columns (file names, places, references).
- A value always has one translation, and no column may map two values to the same French. Check with `node tools/i18n/check-values.js`.
- `mc:import --if-empty` re-imports once when the database still holds English data (`hasFrenchData()` looks for "Ventes").

**Code:**
- The dashboard compares French values (`"Terminé"`, `"Ouvert"`, `"Critique"`…). New code must use the French values; see `translations_fr.json`.
- Key names compared with `e.key` stay English (`"Enter"`, `"Escape"`). Icon names stay English (`icon("Info")`).

**Interface:**
- Strings come from `tools/i18n/ui.fr.*.json`, applied by `tools/i18n/apply-ui.js` (exact literal match, idempotent).
- JSX text, the Data Explorer block (a regex literal confuses the tokenizer) and number formats were fixed by `tools/i18n/fix-*.js`.
- Write new UI text directly in French.
- Formats: `fmt` in `frontend/src/mc/core/ui.ts` gives `30,90 M TND`, `43,9 %`, `22 nov. 2026`, with no-break spaces before units.
- Shell `sed` loses backslashes such as ` ` and `\s`. Use the Edit tool or a node script for those.

**Proof that nothing broke:** `node tools/i18n/equivalence.js` runs the original English engine (exercice3) on English data and the French engine on French data. Every number must match (43 result groups, 0 difference).

**API:** `APP_LOCALE=fr` (local `.env`, `.env.example` and Railway), `backend/lang/fr/validation.php`. Controller messages and audit actions (`Créé`, `Mis à jour`, `Supprimé`) are French.

## Responsive

- **No scaling any more.** `Dashboard.tsx` lets the stage fill the window and re-renders on width changes. Breakpoints live at the end of `frontend/src/mc/visual.less`: ≤ 1024 px tablet (☰ + drawer sidebar, 2-column grids), ≤ 640 px phone (one column).
- **Desktop (> 1024 px) must look exactly like Power BI.** Put every mobile rule inside a media query.
- **New wide content** (tables, boards, charts) must scroll inside its card, never widen the page. `node tools/e2e-mobile.js` fails if any module overflows on phone or tablet, and names the element.
- **Wait a few seconds after `vite build`** before running the UI tests; the first page load can hit the old build.

## Deployment (Railway)

- **Live:** https://web-production-7ed674ac.up.railway.app. Project `mission-control`; services `web` (Dockerfile) and `MySQL`.
- **CLI:** `railway` is installed globally with Node 22 and signed in as the user. Redeploy with `railway up --service web --ci` from `exercice4/`, then run `MC_BASE=<url>/app/ node tools/e2e.js`.
- **Data safety:** never run `migrate:fresh` or a plain `mc:import` on Railway; they wipe users and edits. `start.sh` uses `--if-empty`.
- **Variables live on the Railway service**, including APP_KEY and the DB references. Don't commit them.
- **Don't apply a generic IaC template.** `railway config init` produced one that didn't match the project (wrong name, no MySQL), so it was removed.
- **No config file is used.** The service builds from the Dockerfile; `railway.json` was removed because it is deprecated and was never read.
